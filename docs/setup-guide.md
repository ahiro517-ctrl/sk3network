# セットアップガイド(ワンステップずつ)

この資料は、**あなたが画面の前で手を動かす順** に書いてあります。
1 つずつ終わらせて、最後に動く関係図を手に入れるのが目標です。

所要時間の目安: 30〜45 分。

---

## 全体像

```
[Step 1] Google スプレッドシート新規作成
   ↓
[Step 2] GAS で初期化 + サンプル投入
   ↓
[Step 3] スプレッドシートをウェブに公開(CSV)
   ↓
[Step 4] 各シートの gid を控える
   ↓
[Step 5] web/config.js を作って ID と gid を入れる
   ↓
[Step 6] ブラウザで web/index.html を開く
   ↓
[Step 7](任意)GitHub Pages で限定公開
```

---

## Step 1. Google スプレッドシートを新規作成

1. <https://sheets.new> を開く(または Google ドライブから「新規 > スプレッドシート」)。
2. ファイル名を **`sk3 人脈マップ データ`** にする(任意)。
3. URL の `/d/【ココ】/edit` の **ココ部分(スプレッドシート ID)** をメモ。
   後で `config.js` に貼り付けます。

---

## Step 2. GAS でシート構造を自動生成

仕様書セクション 3・4 にあるシート群を、手作業で作らず GAS で一発生成します。

1. スプレッドシート画面の **拡張機能 > Apps Script** を開く。
2. 開いた Apps Script 画面に最初から書いてあるコード(`function myFunction() {}` など)を **全部削除**。
3. 本リポジトリの [`gas/Code.gs`](../gas/Code.gs) の中身を **全文コピーして貼り付け**。
4. 上部のディスクアイコンで保存。
5. ツールバーの関数選択ドロップダウンで **`setup`** を選び、**▶ 実行**。
6. 初回は権限承認ダイアログが出ます:
   - 「権限を確認」→ Google アカウントを選択
   - 「このアプリは Google で確認されていません」と出たら **詳細 > (プロジェクト名)に移動** → **許可**
7. 「初期化が完了しました」とアラートが出たら成功。
8. **スプレッドシートのタブに戻ってブラウザをリロード**。
   メニューバーに **`sk3`** が追加されているはず。
9. **`sk3 > サンプルデータ投入`** を実行。
   → 人 8 名・プロジェクト 3 件・テーマ 4 件・関わり 17 件が入る。

確認ポイント:
- 「人」「プロジェクト」「テーマ」「関わり」「使い方」の 5 タブができている
- プルダウンが機能している(立場列をクリックしてみる)
- 「人」シートで何か入力すると ID 列が `P001` のように自動採番される

---

## Step 3. スプレッドシートを CSV としてウェブに公開

Web 側がスプレッドシートの CSV を直接 fetch するための公開設定です。

1. スプレッドシート画面で **ファイル > 共有 > ウェブに公開**。
2. ダイアログで:
   - **リンク** タブを開く
   - 範囲: **ドキュメント全体**
   - 形式: **ウェブページ**(個別 CSV 公開ではなく、文書全体を公開すれば
     `export?format=csv&gid=...` で各シートが CSV 取得可能になります)
3. **公開** をクリック → 「このドキュメントを公開してもよろしいですか?」で OK。

> セキュリティ補足
> 公開リンクを知っている人は全データを読めます。仕様書セクション 6.3 のとおり
> URL は **メンバー間限定で共有** してください。
> 現状は内部ビュー実装のみのため、URL の取り扱いには注意。

---

## Step 4. 各シートの gid を控える

1. スプレッドシートで **「人」** タブをクリック。
2. ブラウザのアドレスバーの末尾を見る → `#gid=123456789` のような数字がある。これが **gid**。
3. 同じく **「プロジェクト」「テーマ」「関わり」** タブの gid もそれぞれメモ。

合計 4 つの gid と、Step 1 でメモしたスプレッドシート ID を持っている状態にします。

---

## Step 5. web/config.js を作る

1. このリポジトリの [`web/config.example.js`](../web/config.example.js) を `web/config.js` という名前でコピー。
   ```bash
   cp web/config.example.js web/config.js
   ```
2. `web/config.js` を開いて、次の値を実物に差し替え:
   - `spreadsheetId` ... Step 1 でメモした ID
   - `gids.people` / `gids.projects` / `gids.themes` / `gids.relations` ... Step 4 でメモした gid
3. 保存。

`config.js` は `.gitignore` で除外しているので、リポジトリにはコミットされません。

---

## Step 6. 関係図をブラウザで開く

### 方法 A: ローカルで開く(動作確認向け)

`file://` 直接開きだと CORS の問題が起きる場合があるので、簡易サーバを立てます。

```bash
cd web
python3 -m http.server 8000
# あるいは
npx serve .
```

ブラウザで <http://localhost:8000/> を開く。

### 期待される表示

- 中央のキャンバスに、人(円)・プロジェクト(四角)・テーマ(ひし形)が出る
- 募集中のテーマは外周がパルス(脈打つ)する
- ノードをドラッグで動かせる、ホイールでズーム
- ノードをクリックすると右側に詳細パネル
- 左サイドバーで立場・種別・テーマ状態をフィルタ
- 左下の「俯瞰のヒント」に「sk3 所属だがどこにも紐づいていない人」などが出る

うまく出ない場合は、ブラウザのデベロッパーツールのコンソールでエラーを確認。
左下のステータスに「読み込みエラー」が出る時は、Step 3 の公開設定か、
Step 5 の `gid` が正しいかを見直す。

---

## Step 7.(任意)GitHub Pages で限定公開

メンバーで共有したい場合のデプロイ手順です。

1. このリポジトリの GitHub 設定 > Pages を開く。
2. Source: **Deploy from a branch** を選択。
3. Branch: `main` / Folder: `/` (もしくは `/web`)。
4. 保存。
5. 表示された URL(`https://<user>.github.io/sk3network/web/` など)をメンバーに共有。

> **`config.js` は GitHub に push しないため**、Pages 上で動かすには、
> Pages 用ブランチに `config.js` を別ルートで配置する必要があります。
> セキュリティ上、現時点では「ローカル + 簡易サーバ」での運用を推奨。
> 公開デプロイは後段で別タスク化します。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| ブラウザで真っ暗のまま、左下に「config.js が未設定」 | Step 5 を実施。`config.js` を作成しているか、ファイル名が typo していないか確認。 |
| 「読み込みエラー: 403」「404」 | Step 3 の公開がされていない。あるいは gid が間違っている。 |
| ノードが出ない/極端に少ない | 「関わり」シートの参照 ID が存在しない可能性。GAS メニュー `sk3 > データ点検` を実行。 |
| 日本語が文字化け | 通常起きないが、起きたら CSV のエンコード問題なので報告ください。 |
| 線が多すぎて読めない | 左サイドバーのフィルタで一時的に対象を絞る。仕様上、人 → 人の線は引かないので、混んだら役割やテーマでフィルタするのが推奨。 |
